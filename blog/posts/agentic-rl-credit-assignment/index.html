§ 1

1. 问题定义：为什么 agentic RL 的信用分配要单独成题

1.1 基本设定

一条 agent 轨迹是 $\tau = (s_0, a_0, o_1, s_1, a_1, o_2, \dots, s_{T-1}, a_{T-1}, o_T)$，其中每个 $a_t$ 本身是一段 LLM 生成的 token 序列（thought + tool call），$o_t$ 是环境返回。训练时通常只有终局的可验证奖励 $R(\tau) \in \{0,1\}$。

信用分配问题：把这一个标量 $R(\tau)$ 分解到 token / segment / action / turn / agent 上，得到能指导梯度的稠密信号。

1.2 从 reasoning RL 到 agentic RL 的四个结构性变化

这四点决定了 reasoning RL 的方法无法直接搬到 agentic 场景：

变化reasoning RLagentic RL直接后果
转移的随机性确定性（自回归续写）环境返回 $o_t$ 随机、可能不可复现MC value estimate 需要环境快照/可回滚，否则方差爆炸
可观测性全信息（prompt 已给全）部分可观测（大 codebase、网页只看到一屏）"这一步好不好"依赖训练时才有的特权信息 → 非对称 critic
动作的可逆性每一步都可重采样rm、下单、提交 PR 不可逆从中间状态 branch 采样在很多环境里根本做不到
horizon 与状态重合度500–30K token，单链100+ turn，100K–1M token；不同轨迹很少经过同一状态依赖"同状态分组"的方法（GiGPO 式 anchor grouping）在开放环境失效

1.3 稀疏结果奖励在 agentic 场景的四类失效模式

各篇论文反复指出的是以下四类问题，可作为阅读时的分析清单：

  1. Advantage collapse：一组 rollout 全对或全错 → GRPO 组内优势恒为 0，该 prompt 不产生学习信号（IGPO、PRS/VSPO 明确点出）。
  2. 前缀被污染 / 后缀被漂白：一条失败轨迹里有大量正确的中间决策被一起惩罚；一条成功轨迹里的冗余、回退动作被一起奖励（TRIAGE 明确刻画了这两个盲点；PivoARL 用"隔离错误后缀"来缓解）。
  3. 粒度错配：环境是按 turn 转移的，优化却在 token 级 MDP 上做，importance ratio 和 clipping 都作用在错误的单元上（SORL、Turn-PPO、AEM 的共同出发点）。
  4. 训练不稳定 / 崩塌：off-policy IS 高方差 + 不准的 advantage → 梯度尖峰、entropy 塌陷、"Echo Trap"（RAGEN、SORL、T²PO、Dr. MAS）。

方法界定标准：一个方法是否在做信用分配，看它是否改变了"稀疏结果信号如何落到 token/turn/action/agent 上"。只改变采样、课程或奖励绝对值大小的属于相邻工作（§3 中对这类条目标注为 近核心）。

§ 3

3. 方法族逐篇调研

演进脉络：从分层范式到信号多元化

2024｜范式奠基。ArCHer（2024.02）把"turn 级 critic + token 级 actor"的分层结构引入多轮 LLM RL，确立了 turn 作为信用承载单元的地位；POAD（2024.05）从 Bellman 方程的动作分解给出粒度对齐的理论基础。同年末出现三条后续路线的原型：专家对比型 critic（StepAgent）、segment 级奖励塑形（Adaptive Segment Reward）、LLM 抽取 latent reward（LaRe）。

2025 上半年｜信号工程化。LLM-MCA（2025.02）把 LLM critic 引入多智能体奖励分解；SWEET-RL（2025.03）用训练时特权信息降低 critic 估计难度；RAGEN（2025.04）系统记录了多轮 RL 的 "Echo Trap" 崩塌现象；GiGPO（2025.05）的 anchor state grouping 开创了不训练任何评估器的反事实路线；Turn-Level Reward Design（2025.05）给出了"turn 级稠密奖励优于 token 级"的早期实证。

2025 下半年｜critic-free 与内在信号兴起。iStar（2025.09）用 trajectory-DPO 从偏好对中恢复隐式 step 奖励；TARL（2025.09）让 LLM judge 做 turn 级裁决；IGPO（2025.10）把信息增益确立为内在信用信号。年末注意力转向"信号如何被消费"：粒度对齐（SORL、Turn-PPO）、可验证过程反馈（PRS + VSPO）、关键性筛选（CARL）与多智能体归一化（M-GRPO）同时成形；Agent Lightning（2025.08）则把训练框架问题单独提了出来。

2026 上半年｜方法族爆发与精细化。反事实重采样走向树结构与关键 turn 定位（AT²PO、A³、CRAFT、PivoARL）；内在信号扩展到 belief 变化与技能蒸馏（ΔBelief-RL、ITPO、A²TGPO、SDAR、OPID）；LLM judge 从自由打分收敛到结构化角色归因（SCRIBE、HCAPO、TRIAGE）；多智能体信用分配系统化（MAPPA、Dr. MAS、SHARP、C3、CCPO）。

2026 下半年｜verifier 侧追踪与理论化。2026.07 之后新收录 30 余篇，出现两个上半年没有的方向。其一，从 rollout 侧推断转向 verifier 侧追踪：不再从轨迹侧估计动作重要性，而是打开评估器的内部结构——VICT 沿 verifier 的依赖证明边回传终端信用，RCCA 把 rubric 归因对齐到代码 span 与 token，DRACO 把动态 rubric 的单次轨迹打分闭式重分配到负责的步。其二，理论化：VoT 用策略方差刻画"关键 fork"并给出采样复杂度的精确下界，为 CARL 式 entropy 筛选提供了理论基础；Coverage Not Targeting 提出 verifier 信息密度 V_d，证明在终端验证场景（tau²-bench 实测 V_d≈0.15）下"覆盖"是一阶问题而"定向"是二阶的。同期方法族继续扩张：学习型 critic 进入 GUI / 多模态与 SWE 场景（VisCritic、HyGAE、PRO-CUA、SWE-TRACE），反事实线走向影响依赖图与跨策略持久转移图（IAPO、TIGPO），内在信号线引入贝叶斯校准与信念状态（PBSD、AgentOPSD、ReBel）。

评估的转向：从基准到审计。QVal（2026.06）绕开任务成功率、直接评估稠密信号本身的质量，其"简单 baseline 一致优于较新的稠密监督方法"的结果提供了第一个可复现的信号质量基准。此后审计迅速加深：ASV（2026.07）证明同一 step 奖励换个评估通道符号即可反转（跨通道不一致超同通道 48pp）；Credit Without Ground Truth（2026.08）用执行重放审计发现 LLM-judge、logprob 比率、策略置信度三类信号对 step 贡献的保真度都不显著优于打乱对照，且七臂预注册训练无一臂超过未训练策略——方法比较中的表观差异可能只是"剂量"差异；Coverage Not Targeting（2026.09）则给出了"什么时候才该做定向"的结构判据。四篇合起来把这个领域的方法论门槛整体抬高了一截（详见 §5.2），也是本文 §6.3 结构性判断的直接依据。

A. 学习型评估器：价值函数、PRM 与非对称 critic

共同思路：训练一个额外的模型来预测"从这个状态还能不能成功"，用它的输出或差分做 turn 级奖励/优势。

共同代价：多一个模型的训练与推理；critic 的偏差会直接注入策略梯度。

这一族的技术差异主要体现在"标签从哪来"：TD bootstrapping（AgentPRM）、训练时特权信息（SWEET-RL、CriticSearch）、专家对比（StepAgent）、累加约束（SPA-RL）。

A

ArCHer: Training Language Model Agents via Hierarchical Multi-Turn RL

ICML 20242024.02alphaXiv ↗›
核心问题

主流 LLM RL 方法只优化单轮奖励，结构上无法赋予模型跨多轮寻求信息、做信用分配、反思过去动作的能力；而直接把 PPO 套到长 horizon 上又会因延迟奖励失效。

方法
1采用分层 RL，并行跑两个 RL 算法
2高层是 off-policy、value-based 的 RL，在 utterance（turn）粒度上聚合奖励，学一个 turn 级 value function
3低层是 on-policy 的 token 级策略优化（如 PPO），把高层 value function 当作该 turn 内 token 策略的优化目标
4这个框架是通用的 recipe，替换高/低层算法可衍生出其他方法。

核心问题

1turn-group normalization——在每个 (prompt, turn-index) 组内归一化 IG，使每个 turn 只与同一交互深度的同侪比较
2variance-rescaled discounted accumulation——把累积的归一化 IG 除以累加项数的平方根，使不同 turn 位置的 advantage 幅度可比
3adaptive turn-level clipping——按该 turn 的归一化 IG 调节其 clipping 范围，信息量大的 turn 放宽更新区间、信息量小的收紧。
关键技术创新点

实验设置与主要结果

7 个单跳/多跳开放域 QA benchmark × 3 个 backbone。相对既有 RL 方法平均 +1.75（多跳）/ +1.69（单跳）；自适应 clipping 系数 β=0.3 最优且在 [0.2, 0.4] 内性能波动 <0.15；β=0（固定 clip）时仍优于 GRPO 与 IGPO，说明 turn 分组归一化与方差重缩放本身即有效。

QVal: Cheaply Evaluating Dense Supervision Signals for Long-Horizon LLM Agents

2026.06alphaXiv ↗›
核心问题

目前评估稠密监督方法的通行做法是把它接进一整套训练流水线看下游性能。这有三个问题：昂贵；把监督信号质量与训练工程的混淆因素纠缠在一起；不同方法族需要不同训练设置从而互相不可比。结果是稠密监督方法很少被放在同一基准上比较。

方法
1提出 QVal，一个免训练的测试床，直接评估稠密监督信号本身
2给定一个 state-action 对，QVal 度量该方法的打分是否 Q-aligned——即是否按一个强 reference policy 的 Q 值对动作排序
3这使得在任何训练之前就能比较信号质量，把信号质量与工程选择分离
4实例化为 QVal-v1.0：21 种稠密监督方法、4 个环境、7 个方法族、6 个开源模型骨干，共 1.2K+ 次评估实验。
关键技术创新点

把"信号质量"从"训练结果"中解耦出来测量，用 Q-alignment 作为统一标尺。这是本领域方法论上的重要补位——此前所有方法的比较都建立在不可比的训练结果之上。

实验设置与主要结果

基准覆盖 FrozenLake、ALFWorld、TextWorld 等环境 × 多档模型规模（Qwen3.5-9B 至 122B）× 不同观测模态。两个主要发现：(1) 简单的 prompting baseline 一致优于文献中较新的稠密监督方法；(2) 性能强烈按方法族聚类（族内差异远小于族间差异，code-based 方法例外、方差最大）。这两个结论在不同模型规模、环境、观测模态下都成立。

意义

它直接质疑了 §3.C（内在信号）和 §3.E（LLM judge）中不少方法的实际信号质量——它们的下游增益可能部分来自训练动态的副作用（方差削减、entropy 调节），而非真的更准确地识别了负责的动作。建议新方法在报告任务成功率之外，同时报告信号本身的 Q-alignment。

ASV: Agent Step Value — Auditing Evaluator-Channel Reversals in Black-Box Agent Traces

2026.07alphaXiv ↗›
核心问题

复用 evaluator 产出的 step 奖励时隐含一个假设——打分的方向在更换评估通道（channel）后仍然成立。过程奖励变化的是 agent 状态，evaluator 审计变化的是打分配置，两者各自的一阶差分都无法分离出"状态 × 通道"的交互效应。

方法
1把 Agent Step Value（ASV）定义为通道索引的 target-margin 增益
2在完整匹配的面对（matched faces）上识别"状态 × 通道"交互
3用冻结的 PubMed QA 转移做测试床，两批匹配的 replay 波次检验可复现性。
关键技术创新点

把"评估通道敏感性"从模糊的担忧变成一个可定位、可干预检验的测量问题——在 step 奖励被复用进训练之前，先验证其方向对通道选择是否稳健。

实验设置与主要结果

直接打分通道得到正的均值 ASV，而 generated-view 通道得到负的均值——同一批冻结转移上符号反转；两批匹配 replay 复现该反转；跨通道符号不一致超过同通道重试不一致 48.0 个百分点。匹配的检索面对把反转定位到 generated-view 坐标；一份"仅来源"生成契约可在带 artifact 的检索上恢复正向均值，并消除解析器检出的实质支撑声明。

意义

与 QVal 互补——QVal 问"信号与 Q 值对不对齐"，ASV 问"同一信号换个评估通道，方向会不会反"。对 §3.E（LLM judge 族）尤其相关：judge 的 prompt 与视角选择本身就是通道选择。

Credit Without Ground Truth: Auditing Step-Level Credit Assignment in LLM Agents Against Executed Replay

2026.08alphaXiv ↗›
核心问题

现有评估用人工标注的 step 正确性（correctness）给 step 信号打分；本文改用 step 贡献（contribution）做审计——在每个决策点重采样策略自身的备选动作并前滚，看结果因此改变了什么。两者被证明是分离的。

方法
1在 ALFWorld 中用执行重放（executed replay）构造策略条件化的 ground truth
2审计三类 step 级信号——LLM-judge 打分、结果条件化的 logprob 比率、策略自身置信度
3每个信号都与其边际匹配的打乱对照比较增量保真度
4辅以预注册的七臂训练实验检验"信号用于训练是否有效"。
关键技术创新点

两点方法论贡献。其一，把审计标准从"这步对不对"换成"这步有没有改变结果"——后者才是信用分配该回答的问题。其二，识别出训练比较中的剂量混杂：更稀疏的信用保留的样本更少，优化器步数差出一个数量级——各臂的表观差异与"有效训练剂量"的中介效应统计一致，而非信用内容本身。

实验设置与主要结果

三类信号无一在其打乱对照之上表现出可靠的增量保真度；修正 replay 目标可靠性后，隐式信号保真度上界近零，judge 保真度在已达可靠性下不确定。ground truth 本身是结构化的：30.5% 已定义决策点呈非零 replay 对比；可测性依赖模型（无策略支持反事实的决策点占比 13.1% vs 26.8%，两个相近规模策略差两倍）。失效模式可识别：隐式信用回响的是策略的流利度（中位秩相关 +0.75，第二模型族复现 +0.70），结果条件化不增加因果信息（偏相关 -0.004）。仅置信度路由器以随机水平找回 pivotal step，但每 turn 省 13.1% judge 成本（每轨迹 14.0%）。七臂预注册训练中，无一臂可靠超过未训练策略。

意义

全文最硬的一句话——"比较信用规则必须匹配有效样本量，否则测的是剂量，不是信用。" 这直接指向一大批 CA 论文的实验设计缺陷：稀疏化信用 → 训练样本变少 → 优化步数变少，下游差异可能全部来自这个链条。

Coverage, Not Targeting: A Structural Regime in Multi-Turn Agent Credit Assignment

2026.09alphaXiv ↗›
核心问题

多轮 agentic RL 越来越把信用分配当作定向（targeting）问题——给定终端可验证奖励，把信用定位到"重要的 turn"。本文问一个更前提性的问题：什么时候定向才是对的轴？

方法
1识别出预测这一点的结构量——verifier 信息密度 V_d = k/C（agent 的 C 步因果链中，verifier 能暴露其逐 turn 正确性的比例）
2证明终端状态 verifier 深陷低 V_d 区域，此时定向是错的轴
3在 tau²-bench 上做受控共享 rollout 比较，把奖励密度与信用几何分离开。
关键技术创新点

把"要不要做 turn 级定向"从方法选择问题变成可测量的结构量问题。机制是覆盖（coverage）：终端验证把可观测信号塌缩到单个最终写入 turn（98% 的 rollout 中 k=1），而成功需要 5–8 步前置工具调用链。结论因此是：均匀重分配是零信息覆盖默认值，任何逐 turn 定向方案都必须先打败它——本文贡献了任何定向主张都应通过的"匹配浓度打乱对照"。

实验设置与主要结果

tau²-bench 上，连续稠密奖励均匀铺开优于稀疏二元结果奖励（稀疏奖励在 4/5 种子上净有害），而把同样的 advantage 集中到 progress turn 或随机 turn 上同样有害——定向是二阶的。合成相边界给出交叉点 V_d* ≈ 0.8，而实测 V_d 在 tau²-bench 仅 ~0.15、BFCL V3 仅 ~0.4；BFCL 上均匀同样获胜（匹配浓度打乱对照在 8/8 种子上为负）。跨模型族复现（ToolACE-2-8B，32 个预注册种子 Δ=-0.048；独立 20 种子复现本身显著）；预注册的匹配预算广度扫描呈单调剂量-响应，赤字只在全链覆盖时消失，reward-to-go 臂达到全覆盖平价。

意义

与上一篇构成 2026 下半年的"审计转向"双锚点：一篇说 step 信号的内容可能不含因果信息，一篇说 turn 级定向这个问题框架本身在低 V_d 区域是错的。对 §3.B / §3.C 的 turn 级方法构成前提性质疑——它们都应先报告所处 benchmark 的 V_d。

5.3 除了成功率，还应该报告什么

综合各篇论文的做法，一个完整的评测报告至少应覆盖：

  1. 算力对齐的对照：与 trajectory 级奖励在相同 rollout 数、相同显存下比较（GiGPO 明确报告了这一点）。
  2. 稳定性单列：clipping ratio、gradient norm 尖峰、entropy 曲线（SORL、Dr. MAS、T²PO 的做法）。
  3. 效率单列：达成任务所需 turn 数（TRIAGE 报告减少 10.4%/14.8%；PivoARL 报告减少 42%）——信用分配变好的一个直接表现是 agent 变得更简洁。
  4. 信号质量单独测：QVal 式的 Q-alignment；ASV 式的跨通道符号稳健性；Credit w/o GT 式的打乱对照增量保真度；定向类方法还应通过 Coverage Not Targeting 的匹配浓度打乱对照，并报告所处 benchmark 的 V_d。
  5. Reward hacking 检查：长度、entropy 是否被当作捷径（PRS 用 length-aware BLEU 就是为了防这个）。
  6. 消融要能区分"稠密"与"准确"：TRIAGE 的 ablation 专门证明了增益来自角色分型而非单纯加了稠密奖励。

6.2 五条实践建议

  1. 先做 G 族的粒度对齐，再谈信用分配。如果优化还在 token 级 MDP 上运行而环境按 turn 转移，应先把 importance ratio 和 advantage 挪到 turn 级（Turn-PPO / A²TGPO 的做法）。这一步几乎零成本，且往往比换一个更复杂的信用分配算法收益更大。SORL 的分析表明：粒度错配本身就是不稳定的一个独立来源。
  2. 有 verifier 就一定用 verifier。D 族的信号质量比其他所有族高一个量级。哪怕只能验证一部分动作（比如只能验证工具调用格式是否合法），也值得先把这部分做成稠密奖励——PRS 的 curriculum 就是从"格式正确"起步的。
  3. 没有 verifier 时，C 族是额外成本最低的起点，但需验证信号质量。IGPO / ΔBelief-RL 的实现成本几乎为零（复用 logits）。但 QVal 的结果表明，应在正式训练前先做 Q-alignment 检查，确认 belief 变化确实与"这一步有多好"相关，而不是只在削减方差。
  4. 成功轨迹内部的坏动作值得单独处理。TRIAGE 的 ablation 表明：可靠检测"成功轨迹中的 regression"是其增益的主要来源。多数方法（包括所有纯结果奖励方法）对成功轨迹内所有动作施加相同的正优势，等于在强化冗余和回退行为。
  5. 多 agent 场景下先评估是否必须近似。C3 指出：LLM 多 agent 系统没有隐藏状态，精确反事实是可算的。应优先确认是否真的需要 Shapley 近似或 learned critic——重放历史 + 重采样往往已足够，且成本更低。同时 Dr. MAS 的"per-agent 归一化"应作为默认配置。

6.3 一个需要注意的结构性问题

把 §1.3 的四类失效模式和 §2.2 的八族对照起来看：F 族、G 族、以及 C 族的一部分方法，实际上主要在应对失效模式 3（粒度错配）和失效模式 4（训练不稳），而不是失效模式 1、2。它们改善了梯度的统计性质，但并没有更准确地回答"哪一步该负责"。QVal 的负面结论正是这个观察的量化版本，而 2026 下半年的两篇审计把它进一步尖锐化：Credit Without Ground Truth 证明三类主流 step 信号对"贡献"的保真度不优于打乱对照；Coverage Not Targeting 证明在低 V_d 场景下"定向到哪一步"本身是二阶问题。在更多独立复现出现之前，对"更细的信用必然更好"的主张应默认持保留态度。

因此当某方法报告任务指标提升时，值得区分：它来自更准确的归因，还是来自更小的梯度方差？两者都有价值，但它们是不同的贡献，且后者往往可以用更简单的手段（如 turn 级归一化）达到。

§ 7

7. 开放问题

  1. 信用分配的因果性验证仍是空白。C3 提出的三个诊断指标（credit fidelity、within-group variance、inter-agent influence）和 QVal 的 Q-alignment 是目前仅有的尝试，且都很新。该领域缺乏被广泛接受的"信用分配是否正确"的检验协议。
  2. 不可逆动作环境下的反事实。B 族全部依赖某种形式的重采样/回滚。真实场景（发邮件、下单、改生产库）中做不到。PivoARL 的"局部重试"是一个方向，但它仍需要环境能回到 pivotal state。在完全不可逆的环境里如何做反事实信用分配，目前缺乏系统方法。
  3. 部分可观测下的"这一步好不好"是不是良定义的。非对称 critic（SWEET-RL、CriticSearch）用特权信息绕开了这个问题，但训练/推理的信息不对称会带来分布偏移。更根本的问题是：在 agent 看不到全局的情况下，"最优动作"本身可能依赖它无法获知的信息。
  4. 开放式、不可验证任务。iStar 在 SOTOPIA 上的尝试是少数案例。C 族依赖 gold answer，D 族依赖 verifier，E 族依赖 judge 有明确标准——三条路在真正开放式任务（创意写作、长期陪伴、开放式研究）上都不通。
  5. "停止决策"的信用分配完全缺失。Orchestration Traces 明确报告：截至 2026-05，文献池中没有任何针对"何时停止"的显式 RL 训练方法。而对真实 agent，过早停止和无限循环都是主要失败模式。
  6. Message 级反事实信用在多 agent 中极为稀缺（Orchestration Traces 的另一个发现）。目前多 agent 信用分配停在 agent 粒度，但 agent 之间的具体那一条消息是否有用，没人在做。
  7. 粒度自适应。所有方法都预设了一个固定粒度（token / segment / turn）。但同一条轨迹里，有些 turn 值得细到 token，有些 turn 则整体为噪声。F 族的关键性筛选是朝这个方向的第一步，但还是二元的（选/不选）而非连续的粒度调整。
  8. 算力对齐的公平比较缺失。§6.3 的问题无法回答，根源在于极少有论文在固定 rollout 预算、固定显存、固定 wall-clock 下做对照。GiGPO 是明确报告了显存与时间开销相同的少数案例之一。
